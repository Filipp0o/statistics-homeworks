ECC algorithm and role of the keys
The text is encoded as UTF-8 bytes. Each byte b is represented by the curve point M = (b + 1)G, using a reversible table of 256 points. The private key is k and the public key is Q = kG. This is a simple elliptic-curve ElGamal construction.


  1. Encrypt: for each byte, the sender chooses a fresh random scalar r from 1 to n − 1 and computes R = rG and C = M + rQ. The sender needs Q, but does not need k.
  2. Transmit: send the pair (R, C) for each byte. The ephemeral scalar r remains secret.
  3. Decrypt: the recipient uses k to compute M = C − kR, then looks up the byte associated with M.


C − kR = M + rQ − k(rG)
       = M + r(kG) − k(rG) = M


The random scalar is chosen independently for every byte, avoiding deliberate reuse of the same mask. The curve, generator G and order n are the standard secp256k1 parameters; only the recipient's private-key range is made small. This textbook demonstration does not provide ciphertext authentication.


Caesar algorithm
Represent A–Z by 0–25. Encrypt by adding the shared shift and decrypt by subtracting it:
c = (m + s) mod 26
m = (c − s) mod 26
The same secret shift is used in both directions. Uppercase and lowercase letters are preserved. Spaces, punctuation, digits and non-ASCII letters are left unchanged; the ECC scheme encrypts all UTF-8 bytes.


2. Statistical cryptanalysis of Caesar


The English reference frequencies are computed from Alice's Adventures in Wonderland by Lewis Carroll: 108,082 letters, after removing the Project Gutenberg header and footer and retaining only A–Z. Frequencies are stored with this page.


For each possible shift, count the letters in the candidate plaintext and compare them with the reference distribution. Return the shift with the smallest chi-squared score:
p_i = (corpus_count_i + 0.5) / (corpus_letters + 26*0.5)
score(s) = sum_i (observed_i(s) − L*p_i)^2 / (L*p_i)


L is the number of ciphertext letters. Adding 0.5 to each corpus count avoids a zero expected frequency. The attack uses the ciphertext and the language model; it does not use the original message or the actual shift.


Optional comparison: exhaustive search and bigram scoring


Exhaustive search produces all 26 candidate plaintexts; it does not by itself decide which one is meaningful. Letter-frequency analysis ranks candidates using individual letters. Bigram scoring adds information about adjacent pairs, such as TH or HE, and is implemented below alongside the frequency attack.


ApproachWhat it doesMain limitation
Exhaustive searchDecrypts with every shift from 0 to 25The correct plaintext is included, but a person or scoring rule must identify it

Bigram scoringChooses the smallest mean negative log probability of adjacent letter pairsNeeds representative pair frequencies; very short texts provide few pairs


The bigram model uses the same training book, containing 108,081 adjacent pairs after removing nonletters. Spaces are removed too, so some pairs span word boundaries. There are 26 × 26 = 676 possible pairs. With additive smoothing:


P(ab) = (corpus_pair_count(ab) + 0.5) / (108081 + 676*0.5)
bigram_score(s) = -sum_j log P(candidate_j, candidate_(j+1)) / (L - 1)


Both scores are minimized, but their numerical values use different scales and should not be compared directly. A bigram estimate requires at least two letters.

Effectiveness and limitations
Longer texts usually resemble the language distribution more closely, which helps identify the correct shift. Short texts, names, repeated letters, unusual vocabulary or a different language may produce an incorrect estimate. Bigram scoring uses some ordering information and can improve the estimates, but it is still affected by the training corpus and short samples. Neither score proves that a proposed key is correct.
These success rates apply to the specified texts and samples, not to all English messages. Windows can overlap, and both books are literary English. The training and testing books are distinct, but the experiment does not represent every writing style.


3. Attacking the restricted ECC key space


An attacker who knows the public point Q and that k lies in 1–4096 can enumerate G, 2G, … until jG = Q. The matching j is the private key. The implementation receives only the public point, ciphertext and search bound; it then uses the recovered key to decrypt the message.




candidate = O
for j = 1, ..., B:
    candidate = candidate + G
    if candidate == Q:
        k = j
        decrypt each pair using M = C − kR
        stop


Successive candidates are obtained by one point addition per iteration. The worst-case search requires B comparisons, and the average for a uniformly selected key in 1–B is (B + 1)/2. A bound of 4096 provides only 12 bits of private-key entropy. Failure to find a match means only that the key was not in the searched interval.


This is an exact key-space search, whereas the Caesar attack uses language statistics to select a likely shift. The ECC attack does not depend on the language or ciphertext length to identify k.


With a properly configured secp256k1 scheme, the private scalar is uniformly chosen from 1 to n − 1, where n is close to 2256. Enumerating that range is impractical. Generic classical discrete-log algorithms have a work factor of roughly 2128 group operations. Using the standard curve does not compensate for a deliberately restricted private key.


4. Optional ECC discussion


Alternative attacks on a known key interval


The program implements the linear search in Section 3. The alternatives below attack the same discrete-log problem, but use a different balance of work and memory.


MethodWork for an interval of B candidatesMemory and tradeoff
Linear search, implemented hereO(B) group operationsConstant auxiliary memory; simple and sufficient for B = 4096
Baby-step giant-stepO(√B) group operations and table lookupsStores O(√B) points to exchange memory for less search work
Pollard kangarooExpected work on the order of √B group operationsA probabilistic interval method designed for low storage; constants depend on the variant


For baby-step giant-step, choose m = ceil(√B). Store jG for 0 ≤ j < m and compare Q − imG with this table. A match gives k = im + j, subject to 1 ≤ k ≤ B. With B = 4096, m = 64: this means a table of 64 points and roughly 64 giant steps, rather than thousands of sequential candidates. Even square-root methods become infeasible when the private key is uniformly chosen over the full secp256k1 range.


Which weaknesses come from the key space?


Enumeration succeeds because the recipient's private scalar has only 4096 possible values. This weakness does not depend on English text or repeated letters. A small ephemeral range would create a similar problem: an attacker could search for r from R = rG and then compute rQ. In this implementation, each ephemeral r is instead sampled independently over 1–n−1.


Which weaknesses come from the toy construction?


Textbook ElGamal is malleable: it provides no authentication. If an attacker replaces C with C + G while keeping R unchanged, the recipient obtains M + G. With M = (b + 1)G, this changes the decoded byte from b to b + 1 whenever that byte is valid; for example, an encrypted A can be changed into B. This manipulation does not recover the private key and remains possible even with a large key space.


Reusing the same r across bytes would also reuse rQ. Subtracting two C points would then reveal the difference between their message points, and one known message byte would reveal the shared mask for those bytes. A fresh r per byte avoids that particular reuse problem. The public byte-to-point table is only an encoding: trying the 256 byte values alone does not identify the correct one without a way to determine the mask. Large private keys prevent the interval search; they do not by themselves provide ciphertext authentication.

Both schemes apply a reversible transformation controlled by keys. Caesar is deterministic and preserves the shape of the letter-frequency distribution. ECC encryption is randomized, so encrypting the same message again normally produces different point pairs. However, random-looking ciphertext does not make the restricted-key scheme secure: its private key can still be recovered by enumeration.
